# Revenue Cycle Knowledge Bank — Soft Launch QA Checklist

## Experience and navigation
- [ ] Published homepage loads over HTTPS.
- [ ] Header links work at desktop and mobile widths.
- [ ] Each audience pathway opens the pilot form and preselects the intended audience.
- [ ] Sample mission accepts a choice, explains the reasoning, and allows a retry.
- [ ] Full mission supports both decisions and its return links work.
- [ ] Each master-plan card reveals its detail and status is visible without interaction.
- [ ] Footer and contact links work.

## Pilot form and privacy
- [ ] Confirm Formspree endpoint is active and submissions arrive in the intended inbox.
- [ ] Test required name/email/audience fields and the optional feedback field.
- [ ] Verify updates opt-in is recorded; no prechecked consent.
- [ ] Verify success and error states in a real browser.
- [ ] Confirm no real patient information is requested or needed.

## Content and public claims
- [ ] Homepage distinguishes available, in-development, and planned features.
- [ ] No incomplete weekday series are promoted from homepage navigation.
- [ ] Review archive pages and embedded LinkedIn content before promoting them again.
- [ ] Confirm the free self-learning commitment and optional paid-service distinction.
- [ ] Check source references and effective dates before publishing regulatory lessons.

## Final release
- [ ] Check responsive layout at a narrow mobile width, tablet width, and desktop.
- [ ] Check keyboard focus and reduced-motion behavior.
- [ ] Verify every local href/src reference exists.
- [ ] Run JavaScript syntax checks.
- [ ] Confirm the live deployment, not just local files, passes the checks above.
